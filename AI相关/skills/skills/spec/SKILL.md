生成 STM32F407 固件功能的需求规范文档。这是开发链路的第一步：
`/spec → /new-driver → /flash-debug → /fw-review`。

## 输入

用户用一句话描述想做什么（可以很粗糙），例如"加一路 ADC 采电池电压"。

## 步骤

### 1. 需求访谈（必须做，用 AskUserQuestion 逐个确认）

软件维度：
- **用户故事**：在什么场景下，固件要完成什么动作，期望什么结果？
- **触发方式**：定时任务(FreeRTOS task/timer)、外部中断、串口/总线命令、上电自动？
- **核心流程**：happy path 一步步描述（含上电初始化顺序）
- **异常场景**：传感器无响应、总线超时、数据越界、断电恢复、看门狗复位？
- **数据**：采集/输出什么量，量程、精度、单位、采样率？

硬件/实时维度（嵌入式特有，必问）：
- **引脚分配**：用哪些 GPIO？复用功能(AF)？有无与现有外设冲突？
- **外设资源**：占用哪个 UARTx/SPIx/I2Cx/TIMx/ADCx？是否需要 DMA 通道？
- **中断与优先级**：需要哪些中断？抢占优先级如何排（注意 FreeRTOS 临界区约束）？
- **实时性**：最坏响应时间、采样周期、是否硬实时？放在哪个任务/什么优先级？
- **功耗/时钟**：是否涉及低功耗模式、时钟配置变更？

每个问题等用户回答后再问下一个。"不确定"的标注为待定。

### 2. 代码调研（自动执行，用 Explore subagent，别让用户操心）

- `bsp/` 里相似外设的现有封装模式（如新加 SPI 就看 `bsp/uart.c` 的接口风格）
- 现有引脚/外设/中断占用，**比对防冲突**
- `app/` 里 FreeRTOS 任务的创建与优先级现状
- CubeMX 工程(`.ioc`)当前已启用的外设

### 3. 生成 Spec → 写入 `docs/specs/{功能名}.md`

```markdown
# {功能名}

## 状态
- 创建日期: {日期}
- 状态: 草稿

## 目标 / 非目标
（一句话目标；明确不做什么）

## 用户故事
作为 {角色}，我想要 {操作}，以便 {价值}

## 核心流程
1. 上电初始化：…
2. 运行时：…

## 异常处理
| 场景 | 处理方式 | 是否需看门狗/复位 |
|------|---------|-----------------|

## 硬件资源分配（必填，防冲突）
| 资源 | 占用 | 说明 |
|------|------|------|
| GPIO | PA0(ADC123_IN0) | … |
| 外设 | ADC1 / TIM2触发 | … |
| DMA  | DMA2 Stream0 Ch0 | 内存目标须非 CCM 区 |
| 中断 | ADC_IRQn, 抢占优先级 5 | ≥ configMAX_SYSCALL… |

## 实时性约束
- 采样周期 / 最坏响应 / 所属任务与优先级 / 栈深估算

## 技术设计
### 数据结构
（句柄 struct、缓冲区大小、是否 volatile/对齐）
### 模块接口（bsp 层暴露给 service 的函数）
| 函数 | 入参 | 返回 | 说明 |
### 实现步骤（每步可独立编译/commit）
1. [ ] CubeMX 配引脚/外设/DMA/NVIC，重生成
2. [ ] bsp/{外设}.c 驱动封装
3. [ ] service/{模块}.c 业务逻辑
4. [ ] app 里建任务/接调度
### 参考的现有模式
- {文件路径} — 参考了什么

## 测试计划
- [ ] 主机端：service 层注入 mock bsp 的单测
- [ ] 在板：J-Link 烧录 + 串口打印观测 + 单步验证关键时序

## 待定事项 / MVP 范围
```

### 4. 让用户审阅

把 spec 路径告诉用户，重点请他确认**引脚/外设资源表无冲突**与**中断优先级排布**。
确认后用 `/new-driver` 进入实现。
